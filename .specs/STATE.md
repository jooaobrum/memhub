# Project state

## Decisions

| ID | Decision | Rationale | Status | Date |
| --- | --- | --- | --- | --- |
| AD-001 | Every `Memory` method, reads and review included, takes `workspace_id`, `user_id`, `run_id` (a `CallContext`); `scope(...)` binds them once | asked: "IDs required on every method, or only on writes and search?" - user chose "Required on every method"; prevents cross-user reads by id (PRD D6) | active | 2026-11-11 |
| AD-002 | `Memory(...)` runs no SQL; tables are created only by the idempotent `m.init()` / `memhub init` | asked: "Should Memory(...) create the tables itself, or should the app call m.init()?" - user chose "Explicit m.init()"; no DDL on a borrowed app connection | active | 2026-11-11 |
| AD-003 | A memory-writing tool returns `{"id": <memory_id>, "event", "status"}` to the model, in `MemoryToolkit` and `MemoryMiddleware` alike | asked: "Keep today's tool output, or switch to {id,event,status}?" - user chose "Switch to {id,event,status}"; one write-result vocabulary everywhere (PRD R17) | active | 2026-11-11 |
| AD-004 | memhub never closes a connection or pool it did not open, and commits or rolls back only its own transaction (a savepoint inside the app's) | PRD R2 / TDD "Connections passed in": the app owns pooling, SSL and token refresh | active | 2026-11-11 |
| AD-005 | `Settings.database_url`, `llm` and `embeddings` are optional; with no config, `Memory` uses built-in defaults | asked: "What should Memory(db=, llm=, embedder=) need in PR 1?" - user chose "Defaults, yaml optional"; pulls this slice of PR 2 forward | active | 2026-11-11 |
| AD-006 | In memhub.yaml, a `types:` entry with the name of a preset's type replaces that type whole; a new name is added; `name: null` removes the preset's type | asked: "When `types:` names a type the preset already defines, what happens to that type?" - user chose "Replace that type whole" | active | 2026-11-11 |
| AD-007 | `memhub init --db` accepts a URL with a literal password and writes it as given; N2's refusal covers only keys named `password`, `api_key`, `token`, `secret` | asked: "Accept and write ${MEMHUB_DB_PASSWORD}, write as given, or refuse?" - user chose "Accept and write the URL as given"; departs from PRD success criterion "a config written by init contains no secret values" for URLs | active | 2026-11-11 |
| AD-008 | The `assistant` preset is built from `examples/habitantes` (user-scope chatbot: profile, preference, fact, episode, case, skill) | asked: "Which should the assistant preset be built from?" - user chose "habitantes: user-scope chatbot" | active | 2026-11-11 |
| AD-009 | In PR 2, `memhub doctor` checks the ledger tables and the stored embedding model/dims; the numbered DB schema version is added to doctor in PR 6 | asked: "What should doctor check for the schema in this PR?" - user chose "Tables + embedding meta" | active | 2026-11-11 |
| AD-010 | `memhub doctor` warns about a pool passed via `connect:` whose `max_lifetime` is unset, 0 or >= 3600 s | asked: "When should doctor warn about pools with no max_lifetime?" - user chose "max_lifetime unset, 0 or >= 3600 s"; psycopg_pool's default of 3600 equals an Entra token's life | active | 2026-11-11 |
